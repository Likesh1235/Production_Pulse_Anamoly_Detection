# Production Pulse — REST API

FastAPI backend for the Production Pulse autoencoder anomaly detector.

> **Status (2026-10-21):**
> * **Written:** the code and this document.
> * **Tested:** the automated API tests passed on Windows (`.venv313`) as part of the full suite (371 collected: 369 passed, 2 skipped, 0 failed). They use a stub detector and a tiny model trained on synthetic data.
> * **Not done:** the API has **not been started as a live server** by the verification scripts, **no model has been trained** on the TEP data, and the dashboard has never been connected to it.
> * Until notebook 03 is run and saves a model, the API starts in "model unavailable" mode. The example responses below show the *format* only; the numbers in them are placeholders, not results.

---

## 1. Architecture

```
src/production_pulse/api/
├─ app.py        create_app(): config + env overrides, CORS, error handlers, lifespan (loads the model once)
├─ routes.py     HTTP endpoints only (validation → service → store)
├─ service.py    ModelService: model lifecycle (ModelState snapshots, atomic reload) + prediction logic
├─ store.py      PredictionStore: SQLite history (parameterised SQL, indexes, per-call connections)
├─ schemas.py    Pydantic request/response models (strict numeric validation)
├─ settings.py   PP_API_* environment overrides, admin token (env only)
├─ errors.py     uniform JSON errors; no stack traces or file paths in responses
├─ main.py       ASGI entry point (uvicorn production_pulse.api.main:app)
└─ __main__.py   python -m production_pulse.api
src/production_pulse/reporting.py   evaluation reports written by notebooks, served by GET /metrics
```

**Prediction path.**
1. The request JSON is validated (numeric, finite values, no extra keys).
2. Feature names are checked against the 52 canonical names and reordered into the model's order.
3. Scoring uses `AutoencoderDetector.detect_raw(frame, check_unseen=False)`. This is the same scaler and scoring as the notebooks, with the evaluation-only leakage refusal turned off for live inference.
4. The per-feature contributions come from `reconstruction_errors`.
5. The result is stored in SQLite and returned.

**Model lifecycle.**
* The model is loaded once at startup with `AutoencoderDetector.load(model_dir, paths=..., expected_feature_columns=FEATURE_COLUMNS)`. It is never trained by the API.
* It is marked **ready** only if it loaded, its feature order matches the canonical one, a fitted scaler with the same feature order is attached, and a finite calibrated threshold exists.
* Each request works on a snapshot of the model state. A model is replaced only at startup or through `POST /model/reload`, never silently.

| `model.status` | meaning |
|---|---|
| `ready` | predictions enabled |
| `not_found` | no `metadata.json` in `model_dir` (no trained model yet) |
| `load_failed` | the artifact is corrupt, failed its checksum or schema check, or could not be read |
| `dependency_missing` | TensorFlow/Keras are not importable |
| `incompatible` | the feature schema or the scaler does not match the 52-feature order |
| `no_preprocessing` | the artifact has no fitted scaler |
| `not_calibrated` | there is no finite threshold |
| `not_loaded` | loading was disabled (tests/tools only) |

## 2. Model setup

1. In JupyterLab (port 8889, kernel `.venv313`), run `notebooks/03_autoencoder_training.ipynb` from top to bottom.
   * It trains on normal training runs, calibrates the threshold on calibration runs, and saves to `artifacts/models/autoencoder_v1/` (`model.keras`, `metadata.json`, `history.csv`, `fingerprints.npz`).
   * Section 6b writes the measured metrics to `reports/evaluation_metrics.json`, which `GET /metrics` serves.
2. Start the API (§3). `GET /health` should report `"model": {"available": true, "status": "ready"}`.
3. If you replace the model while the API is running, either restart the API or call `POST /model/reload` (§4.3).

## 3. Running the API (Windows PowerShell, `.venv313`)

Run these from the project folder:

```powershell
cd "<project folder>"

# Option A - Uvicorn directly (host/port on the command line)
.\.venv313\Scripts\python.exe -m uvicorn production_pulse.api.main:app --app-dir src --host 127.0.0.1 --port 8000

# Option B - host/port taken from configs/default.toml [api] (+ PP_API_* overrides)
$env:PYTHONPATH = "src"
.\.venv313\Scripts\python.exe -m production_pulse.api
```

Then open **http://127.0.0.1:8000/docs**, the interactive API documentation generated by FastAPI. Stop the server with `Ctrl+C`.

Port 8888 is used by another program and JupyterLab is on 8889, so the API uses **8000** by default.

### Configuration (`configs/default.toml` → `[api]`) and environment overrides

| setting | default | env variable |
|---|---|---|
| host | `127.0.0.1` | `PP_API_HOST` |
| port | `8000` | `PP_API_PORT` |
| max_batch_size | `1000` | `PP_API_MAX_BATCH_SIZE` |
| model_dir | `artifacts/models/autoencoder_v1` | `PP_API_MODEL_DIR` |
| database_path | `data/api/predictions.sqlite3` | `PP_API_DATABASE_PATH` |
| metrics_report | `reports/evaluation_metrics.json` | `PP_API_METRICS_REPORT` |
| cors_origins | `http://localhost:5173`, `http://127.0.0.1:5173` | `PP_API_CORS_ORIGINS` (comma-separated) |
| store_inputs | `false` | `PP_API_STORE_INPUTS` |
| top_features | `5` | — |
| history page size (default/max) | `50` / `500` | — |
| admin token (secret) | *(not set → reload disabled)* | `PP_API_ADMIN_TOKEN` (≥ 16 chars, **env only**) |

Rules for these values:
* Paths must be relative to the project root.
* The database must lie inside an output folder (`data/`, `artifacts/`, `reports/`, `logs/`); the API refuses original files and `.RData` names.
* `"*"` is not accepted as a CORS origin.
* Invalid values stop the API at startup with a clear error.

Example overrides for the current PowerShell session only:

```powershell
$env:PP_API_PORT = "8001"
$env:PP_API_ADMIN_TOKEN = "choose-a-long-random-string-here"
.\.venv313\Scripts\python.exe -m uvicorn production_pulse.api.main:app --app-dir src --port 8001
```

## 4. Endpoints

### 4.1 `GET /health`
The API is up whenever this answers `"status": "ok"`. Model and database availability are reported **separately**.
```json
{
  "status": "ok",
  "api_version": "0.1.0",
  "model": {"available": false, "status": "not_found",
            "reason": "No trained model was found in the configured model directory. Train and save one with notebooks/03_autoencoder_training.ipynb."},
  "database": {"available": true, "status": "ready", "reason": null}
}
```

### 4.2 `GET /model/status`
Returns availability, the feature schema, and the saved metadata. **Keys that are missing from the artifact are left out, never filled in.** The scaler is described by its method and source only; its parameters are not returned.
```json
{
  "available": true, "status": "ready", "reason": null,
  "model_dir": "artifacts/models/autoencoder_v1",
  "feature_schema": {"n_features": 52, "feature_columns": ["xmeas_1", "...", "xmv_11"]},
  "model_id": "<first 12 hex chars of the model checksum>",
  "loaded_utc": "<timestamp>",
  "metadata": {
    "model_type": "dense_autoencoder", "created_utc": "<timestamp>",
    "settings": {"hidden_layers": [32, 16], "bottleneck": 8, "...": "..."},
    "training_summary": {"epochs_run": "<n>", "best_epoch": "<n>", "best_val_loss": "<value>"},
    "threshold": "<calibrated value>", "threshold_source": "calibrated: target FPR 0.01 on <n> calibration-normal rows",
    "library_versions": {"tensorflow": "...", "keras": "...", "numpy": "...", "pandas": "..."},
    "preprocessing": {"method": "standard", "fit_source": "fault_free_training / train split", "n_samples_fit": "<n>"}
  }
}
```

### 4.3 `POST /model/reload`
Deliberately reloads the model from `model_dir`. Requires the header `X-Admin-Token: <PP_API_ADMIN_TOKEN>`.
* Without a configured token it returns **403** `reload_disabled`.
* With a wrong or missing token it returns **401** `unauthorized`.

```powershell
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8000/model/reload -Headers @{ "X-Admin-Token" = $env:PP_API_ADMIN_TOKEN }
```

### 4.4 `POST /predict`
Send either one sample or a batch (at most `max_batch_size` samples). **Raw** sensor values go in; the API applies the model's own training scaler. Feature names may come in any order.

One sample:
```json
{"features": {"xmeas_1": 0.25, "xmeas_2": 3664.0, "...": "all 52 features", "xmv_11": 18.0}, "sample_id": "line-3-t0001"}
```
A batch:
```json
{"samples": [{"features": {"xmeas_1": 0.25, "...": "..."}, "sample_id": "a"},
             {"features": {"xmeas_1": 0.27, "...": "..."}}]}
```
Response (format only):
```json
{
  "request_id": "5f0c...", "model_id": "1a2b3c4d5e6f",
  "threshold": "<float>", "threshold_source": "calibrated: ...",
  "n_samples": 2, "n_anomalies": "<int>", "history_stored": true, "warnings": [],
  "results": [
    {"index": 0, "sample_id": "a", "prediction_id": 17,
     "reconstruction_error": "<float>", "is_anomaly": false, "threshold": "<float>",
     "top_features": [{"feature": "xmeas_9", "squared_error": "<float>", "share": "<0..1>"}]}
  ]
}
```
* `reconstruction_error` is the mean squared reconstruction error over the 52 scaled features.
* `is_anomaly` is `reconstruction_error > threshold`.
* `top_features` lists the features with the largest squared error and their share of the sample's total.
* If the history database fails, predictions are still returned, with `history_stored: false` and a warning.

PowerShell example (sends the first row of the fault-free testing file):
```powershell
$env:PYTHONPATH = "src"
$body = .\.venv313\Scripts\python.exe -c "import json; from production_pulse.data import load_raw_dataset, FEATURE_COLUMNS as F; r = load_raw_dataset('fault_free_testing').iloc[0]; print(json.dumps({'features': {c: float(r[c]) for c in F}}))"
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8000/predict -ContentType "application/json" -Body $body
```
Note: rows from the **evaluation and holdout runs** should be reserved for the final evaluation and the live demo.

### 4.5 `GET /metrics`
Returns the latest saved evaluation report, or an explicit unavailable status:
```json
{"available": false, "reason": "No evaluation report has been saved yet."}
```
```json
{"available": true, "report": {"report_version": 1, "generated_utc": "...", "source": "notebooks/03_autoencoder_training.ipynb",
                                "model_id": "...", "metrics": {"...": "values measured by the notebook"}}}
```

### 4.6 `GET /history`
Stored predictions, **newest first** (ordered by row id).

| query | default | rule |
|---|---|---|
| `limit` | 50 | 1 – 500 |
| `offset` | 0 | ≥ 0 |
| `before_id` | — | ≥ 1; returns rows with `id < before_id` (stable paging while new rows arrive) |
| `anomalies_only` | false | only rows flagged as anomalies |

```json
{"items": [{"id": 18, "created_utc": "...", "request_id": "...", "sample_index": 1, "sample_id": null,
            "reconstruction_error": "<float>", "threshold": "<float>", "is_anomaly": true,
            "model_id": "...", "top_features": [{"feature": "xmeas_1", "squared_error": "<float>", "share": "<float>"}]}],
 "total": 18, "limit": 50, "offset": 0, "next_before_id": null}
```
Raw sensor values are **not** stored unless `store_inputs = true`.

## 5. Errors

Every error has the same shape, and none includes a stack trace or a file path:
```json
{"error": {"code": "<machine-readable code>", "message": "<human-readable text>", "details": "<optional>"}}
```

| HTTP | code | when |
|---|---|---|
| 422 | `validation_error` | malformed JSON body/query; non-numeric (`"1.5"`, `true`, `null`, lists) or non-finite (`NaN`, `Infinity`, overflow) values; both or neither of `features`/`samples`; unknown keys |
| 422 | `invalid_features` | missing or unexpected feature names (listed per sample) |
| 422 | `value_out_of_range` | finite values so large that the float32 model overflows (e.g. `1e300`); nothing is scored or stored; `details` lists sample and features |
| 413 | `batch_too_large` | more than `max_batch_size` samples |
| 503 | `model_unavailable` | the model is not ready (`details.model_status` says why) |
| 503 | `database_unavailable` | history requested while the database is unavailable |
| 401 / 403 | `unauthorized` / `reload_disabled` | model reload |
| 404 | `not_found` | unknown route |
| 405 | `method_not_allowed` | known route, wrong HTTP method (for example `GET /predict`) |
| other 4xx/5xx raised by the framework | `http_error` | any other framework-level HTTP error; `message` carries the framework's text |
| 500 | `internal_error` | unexpected failure (details go to the server log only) |

Example: a missing feature in sample 0 and an extra feature in sample 1:
```json
{"error": {"code": "invalid_features",
           "message": "Each sample must contain exactly the 52 TEP measurement features (any order).",
           "details": [{"sample_index": 0, "missing_features": ["xmv_3"]},
                       {"sample_index": 1, "unexpected_features": ["simulationRun"]}]}}
```
Example: a text value:
```json
{"error": {"code": "validation_error", "message": "The request is invalid.",
           "details": [{"location": ["body", "samples", "0", "features"],
                        "message": "non-numeric value(s) for: ['xmeas_4']", "type": "value_error"}]}}
```

## 6. Connecting the React frontend (Phase 7)

* The development server origin must appear in `cors_origins`. The defaults cover Vite (`http://localhost:5173`, `http://127.0.0.1:5173`). For another port, set e.g. `$env:PP_API_CORS_ORIGINS = "http://localhost:3000"`.
* Base URL: `http://127.0.0.1:8000`. Put it in the frontend environment as `VITE_API_BASE_URL=http://127.0.0.1:8000` rather than hard-coding it.
* Suggested calls:
  * `GET /health` on load, showing API, model and database state separately;
  * `GET /model/status` for the model card;
  * `POST /predict` with batches up to `max_batch_size`;
  * `GET /history?limit=50`, then `before_id=<next_before_id>` for "load older";
  * `GET /metrics`, showing "No evaluation report yet" when `available` is false.
* Always check `error.code`: on `model_unavailable` show `error.message` (for example "train the model first") instead of a generic failure.

```js
const API = import.meta.env.VITE_API_BASE_URL ?? "http://127.0.0.1:8000";
const res = await fetch(`${API}/predict`, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ samples }),            // samples: [{ features: {...52 values...} }]
});
const data = await res.json();
if (!res.ok) throw new Error(data.error?.message ?? `HTTP ${res.status}`);
```

## 8. Known limitations

* There is no authentication on the read and predict endpoints; the API is meant for local, development or demo use on `127.0.0.1`.
* There is no request-body size limit beyond `max_batch_size`; FastAPI parses the JSON before that check.
* Inference is serialised by a lock, so throughput is bounded by single-threaded Keras inference.
* History is append-only, with no retention or cleanup policy yet.
* SQLite on a OneDrive-synced folder may be briefly locked during sync; such writes fail softly (`history_stored: false`).
